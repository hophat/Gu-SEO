feat: v1.16.0 — publish report email to the project's own users

When a scheduled post goes live, the people who own the project get an email:
the article, its link, and a line per social channel with its real status,
the external post link, and the failure reason if there is one.

Recipients are `users.project_id`, not the super_admin who happens to be logged
in. Only posts created from a calendar slot are reported — the calendar is the
operator's standing instruction, while a post they published by hand is one
they already watched happen. The signal worth mailing about is "the thing you
scheduled weeks ago went out".

The report is sent AFTER the distribution queue drains, not before. Sent first
it would always say "pending", which is the one thing a report must not do; if
a channel is still retrying, the email says so and gives the attempt count.

Errors sending mail are deliberately swallowed: a broken SMTP server must not
turn a successful publish into a failure.

Refactors email_smtp.js to expose sendEmail({ to, subject, html }). sendOtpEmail
had the whole SMTP handshake inline, so a second message type meant a second
copy of it. cloudflare:sockets is now imported lazily — it only resolves inside
Workers, so the static import made the module unloadable anywhere else,
including tests.

Adds POST /api/admin/report/test so the path is verifiable rather than assumed:
no arguments sends a sample, with a blog_post_id it runs the real report.
